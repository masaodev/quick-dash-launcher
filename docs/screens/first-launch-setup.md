## 1. 概要

初回設定画面は、QuickDashLauncherを初めて起動した際に表示される画面です。「ようこそ」「ホットキー」「試してみる」の 3 ステップで、何をするソフトかを伝え、起動ホットキーと自動起動を決めてもらいます。最初に起動したときにのみ表示され、設定完了後は通常のランチャーが表示されます。

### 主要機能

- **ようこそ**: 何をするソフトか（1 行の説明と特徴 3 つ）を伝える
- **ホットキー**: 起動ホットキー（既定: Alt+Space）を決める。ウィンドウ検索のホットキー（既定: Ctrl+Alt+Space）は折りたたみの中で決められる。「次へ」で起動ホットキーを登録してみて、ほかのアプリが使っていれば先へ進まない
- **試してみる**: 決めたキーを押すと ✓ を出し、「使いはじめる」が押せるようになる。自動起動（既定: 有効）と更新の知らせ（既定: 有効。Store 版では出さない）を決めて「使いはじめる」で完了する
- **強制設定**: ESCキー、フォーカス喪失、起動ホットキーのいずれでも隠れず、設定完了が必須

## 5. 機能詳細

### 5.1. ステップの移動

- ようこその「次へ」でホットキーへ、ホットキーの「戻る」でようこそへ、試してみるの「戻る」でホットキーへ移る
- ホットキーの「次へ」は、起動ホットキーを登録してから移る（[5.3](#53-ホットキーの次へボタン押下)）
- 入力したホットキー・自動起動のチェックは、ステップを行き来しても保つ。試してみるの ✓ は保たず、入り直すと消えるので、もう一度キーを押す

### 5.2. 起動ホットキーの入力欄への入力

#### アクション

- 起動ホットキーの入力欄をクリックし、キー組み合わせを入力

#### 処理フロー

1. 入力欄をクリックすると録画を開始し、欄に「キーを押してください…」を表示（右に「キー入力待ち…」と「キャンセル」ボタンを表示）
2. 録画中に押したキーを「Ctrl + Alt + Q」の形で表示し、修飾キーと通常キーがそろった状態でキーを離した時点でホットキー（例: `Ctrl+Alt+Q`）として確定して録画を終了（「キャンセル」ボタンを押す、またはフォーカスが外れると録画をやめ、元の値のまま）
3. 確定したホットキーを、上のキーの表示にも反映し、登録失敗のエラーを消す
4. 確定したホットキーのバリデーションを実行:
   - 空チェック
   - 形式チェック（使えるキー名の組み合わせか）
   - 修飾キーの有無チェック
5. バリデーション結果を表示:
   - 有効な場合: エラー表示なし、「次へ」ボタン有効化
   - 無効な場合: エラーメッセージ表示、「次へ」ボタン無効化

入力欄は管理ウィンドウの設定タブと共通の部品で、録画の開始・確定・キャンセルの細かい挙動は [ホットキー入力](./hotkey-input.md) を参照。

#### バリデーション詳細

形は「修飾キー 1 つ以上 + 通常キーちょうど 1 つ」。空のとき、修飾キーがないとき、通常キーがない・2 つ以上あるとき、知らないキー名のときは、入力欄の下に理由を表示する。チェックと文言の一覧は [ホットキー入力 - バリデーション](./hotkey-input.md#44-バリデーション) を参照。ほかのアプリと重なっているかは、ここでは見ない（[5.3](#53-ホットキーの次へボタン押下) で登録してみて確かめる）。

**有効なキーパターン**:

- 修飾キー: `Ctrl`, `Alt`, `Shift`, `CmdOrCtrl`, `Command`, `Cmd`
- 通常キー: `A-Z`, `0-9`, `Space`, `Enter`, `Tab`, `Escape`, `Delete`, `Backspace`, `F1-F12`

#### 既定値

- 初期表示: `Alt+Space`（保存先の項目と設定ファイル上の既定値は[設定ファイル形式](../architecture/file-formats/settings-format.md#32-ホットキー設定)）

### 5.3. ホットキーの「次へ」ボタン押下

#### 処理フロー

1. 両ホットキーのバリデーション状態を確認（無効ならボタンが押せない）
2. 起動ホットキーを登録する（設定ファイルにも保存する。管理ウィンドウでホットキーを変えるときと同じ処理）。登録中はボタンと入力欄を無効にする
3. 登録できなかったら（ほかのアプリが同じキーを使っているなど）、先へ進まず、キーの表示の下に赤字で「このキーはほかのアプリが使っています。別のキーを選んでください。」を出す。キーを入力し直すと消える
4. ウィンドウ検索のホットキーが入力されていれば、使えるか（ほかのアプリ・起動ホットキーと重ならないか）を登録せずに確かめる（[5.8](#58-ウィンドウ検索のホットキー入力欄への入力)）。使えなければ、先へ進まず、折りたたみを開いて入力欄の下に赤字を出す。キーを入力し直すと消える
5. どちらも通ったら試してみるへ進む

#### 補足

- ホットキーをここで登録するので、試してみるで実際に押して確かめられる。初回起動モードは「使いはじめる」まで続く
- 試してみるから「戻る」で別のキーに変えて「次へ」を押すと、前のキーの登録を外して新しいキーを登録する
- 起動ホットキーを無効にして起動しているとき（E2E。環境変数 `DISABLE_GLOBAL_HOTKEY=1`）は、登録せずに設定ファイルへの保存だけ行い、成功として扱う

### 5.4. 試してみるで起動ホットキーを押す

#### 処理フロー

1. 試してみるを表示している間に起動ホットキーが押される
2. メインプロセスは初回起動モードなのでウィンドウを隠さず、レンダラーに「押された」ことを知らせる
3. 画面の表示を「✓ 呼び出せました」に変える

✓ が出るまで「使いはじめる」は押せない（キーで呼び出せることを確かめてから使いはじめてもらうため）。固定モード（常に最前面・表示固定）で起動していても同じく ✓ を出す（ホットキーを押したときの判定で、初回起動モードを固定モードより先に見る。固定モードで起動するのは環境変数 `WINDOW_PIN_MODE` を付けたときだけ）。キーを押しても出ないときは、「戻る」で別のキーを選び直す。ほかのステップにいる間に押しても、ウィンドウは隠れず表示も変わらない。

### 5.5. 「使いはじめる」ボタン押下

#### 処理フロー

1. 入力されたホットキー、ウィンドウ検索ホットキー、自動起動設定、更新の知らせ（Store 版では保存しない）を設定ファイルに保存する。保存と一緒に、次のことが起きる
   - 自動起動設定を適用する（スタートアップフォルダへのショートカット作成/削除。Store 版では Windows のスタートアップ アプリへの登録を有効/無効にする）
   - 初回起動モードを終了する
   - ウィンドウを初回設定用の 700x600 から設定の大きさ（既定 600x400）に戻す（中心は保つ）
2. 起動ホットキーを登録（[5.3](#53-ホットキーの次へボタン押下) で登録済みのキーなので、そのまま）。ウィンドウ検索のホットキーが入力されていれば、それも登録
3. 初回設定画面を非表示にして、ランチャーに遷移
4. アイコンが未取得のアイテムのアイコンを全タブ分、自動で取りに行く（ランチャーの「アイコン未取得」の通知の「取得する」と同じ処理。初回のお試し用のアイテムにはアイコンがまだないため）。利用者が頼んだ処理ではないので、進捗バーは出さずに裏で取る。取っている間はランチャーの「アイコン未取得」の通知も出さない（取り終えても取れなかったものがあれば、そのとき出す）

データファイルタブは、起動時にウィンドウを作る前に決めてある（[5.6](#56-初回起動チェック)）。このボタンでは書き直さない。

#### エラーハンドリング

- 設定保存失敗時: 初回設定画面のボタンの上に赤字で「設定を保存できませんでした。もう一度「使いはじめる」を押してください。」を出し、「使いはじめる」「戻る」・自動起動と更新の知らせのチェックを押せる状態に戻す。もう一度押すと保存し直す（初回設定の間はダイアログを描かないので、画面の中に出す）

### 5.6. 初回起動チェック

#### アクション

- アプリケーション起動時に自動判定

#### 処理フロー

1. スプラッシュウィンドウを表示
2. 設定ファイルから起動ホットキーを読み込む
3. ホットキーが空または未設定の場合:
   - 初回起動モードを有効化
   - スプラッシュウィンドウ終了後、初回設定画面を表示
4. ホットキーに値がある場合:
   - 通常モードで起動
   - ランチャーを表示

#### 表示判定

- **初回起動**: ホットキーが空または未設定 → 初回設定画面
- **2回目以降**: ホットキーに値がある → ランチャー
- ホットキーの「次へ」で起動ホットキーを保存するので、試してみるの途中で終了すると、次の起動では初回設定画面を出さない
- 初回設定画面をもう一度出したいときは、設定ファイルの起動ホットキーを空にして再起動する（項目は [設定ファイルの形式](../architecture/file-formats/settings-format.md#32-ホットキー設定)）
- 起動時にデータファイル（`datafiles/data.json`）がなければ、お試し用のアイテム入りで作る（中身はコードを正とする）。名前と URL は作るときの表示言語で決まる（日本語は名前に読みのローマ字を添え、日本向けのサイトにする）
  - **初回起動**: Web のアイテム（Google 検索・Google マップ・天気予報）を `datafiles/data2.json` に分け、ほかを `data.json` に入れる。`data2.json` が既にあれば分けずに全部 `data.json` に入れる
  - **2回目以降**: 全部 `data.json` 1 つに入れる
- 初回起動でデータファイル（`data.json`）を作ったときは、ウィンドウを作る前にデータファイルタブを表示言語の名前で決める。初回設定の途中で終了して起動し直したときは、`data.json` が既にあるので決め直さない（作ったときのタブを保つ）。タブは「メイン」（`data.json`）と、Web のアイテムを分けたときは「Web」（`data2.json`）。データファイルの名前は「〈タブ名〉用データファイル」（英語ではタブ名が `Main`、データファイルの名前が `Main data file`）
- 初回起動でデータファイル（`data.json`）を作ったときは、ワークスペース（`workspace.json`）が無ければ、お試し用のグループとアイテム入りで作る（中身はコードを正とする。[ワークスペース機能](../features/workspace.md#初回起動のお試し)）。ワークスペースを最初に読む前に書く。`workspace.json` が既にあれば作らない

### 5.7. 自動起動設定の変更

#### 処理フロー

1. チェックボックスの状態を切り替え（チェック/未チェック）
2. 選択状態は画面内で保持し、この時点では保存しない
3. 「使いはじめる」押下時に設定ファイルに反映

#### 既定値

- 初期表示: 有効（チェックあり）。ランチャーは起動していないとホットキーで出せないため。設定ファイル上の既定値（無効）とは別

#### 設定の反映

- 「使いはじめる」押下時に設定ファイルへ保存（保存先の項目は[設定ファイル形式](../architecture/file-formats/settings-format.md#34-自動起動cli-設定)）
- 有効ならWindowsのスタートアップフォルダにショートカットを作成し、無効なら削除（Store 版の動きは[管理ウィンドウ 5.4](./admin-window.md#54-自動起動チェックボックスを変更)）
- 設定タブでいつでも変更可能

### 5.8. ウィンドウ検索のホットキー入力欄への入力

#### アクション

- 折りたたみを開き、ウィンドウ検索のホットキー入力欄をクリックしてキー組み合わせを入力（または「使わない」ボタンで削除）

#### 処理フロー

1. 入力欄をクリックすると録画を開始する（空でもよい、「使わない」ボタンで消せる）
2. 修飾キーと通常キーがそろった状態でキーを離した時点でホットキー（例: `Ctrl+Alt+S`）として確定する。録画の開始・確定・キャンセルの細かい挙動は [ホットキー入力](./hotkey-input.md) を参照
3. 確定したホットキーのバリデーションを実行:
   - 空文字列の場合は有効（設定しないことが可能）
   - 入力がある場合は形式チェック・修飾キー有無チェック
4. バリデーション結果を表示:
   - 有効（または空）: エラー表示なし
   - 無効: エラーメッセージ表示、「次へ」ボタン無効化

#### 既定値

- 初期表示: `Ctrl+Alt+Space`（設定ファイルの既定値と同じ）。折りたたみを開かずに進めば、この値で完了する

#### 設定の反映

- 「使いはじめる」押下時に設定ファイルへ保存（保存先の項目は[設定ファイル形式](../architecture/file-formats/settings-format.md#310-追加ホットキー設定)）
- 空のまま完了した場合は、ウィンドウ検索のホットキーは使えない
- 初回設定を完了するまでは、ウィンドウ検索のホットキーを登録しない（既定値が入っていても、この画面の途中でウィンドウ検索が開かないようにするため）。完了時に登録する。ほかのアプリと重なっていないかは、ホットキーの「次へ」で登録せずに確かめる（[5.3](#53-ホットキーの次へボタン押下)。`settings:is-item-search-hotkey-available`）
- 初回設定後、設定画面からいつでも変更可能

### 5.9. ESCキー/フォーカス喪失の無視

#### アクション

- ESCキーまたは起動ホットキーを押下、またはウィンドウからフォーカスが外れる

#### 処理フロー

1. メインプロセスで初回起動モードが有効かチェック
2. 初回起動モードの場合:
   - ESCキーによるウィンドウの非表示を無視
   - フォーカス喪失によるウィンドウの非表示を無視
   - 起動ホットキーではウィンドウを隠さず、レンダラーに押されたことを知らせる（[5.4](#54-試してみるで起動ホットキーを押す)）
3. 通常モードの場合:
   - 通常通りウィンドウを非表示

#### 目的

- ユーザーが初回設定を完了するまで、誤ってウィンドウを閉じないようにする
- 設定完了を強制することで、アプリケーションの正常な動作を保証
