# 画面仕様書 執筆ガイドライン

画面仕様書（`docs/screens/`）を書くときの決まり。docs 全体の置き場と参照方向は [ドキュメントの役割分担](../README.md#ドキュメントの役割分担)、変更に合わせて直す文書は [変更したときに直す文書](../README.md#変更したときに直す文書)、コードと照合して直すときの決まりは `.claude/skills/docs-check/references/verify.md` を正とする。

## 基本方針

画面仕様書は、利用者から見た**機能・挙動**を書く文書で、コードの説明書ではない。

- 何をすると何が起こるか（ユーザー操作に対する動作）
- 画面がどう変わるか（状態遷移）
- いつ何が見えるか（表示条件・表示内容）
- エラーのとき何が出るか

ボタン名・メニュー名・メッセージなどの表示文言は、コードの文字列どおりに書く。

---

## コード上の名前を本文に書かない

API・IPC チャンネル・関数・状態・イベントハンドラ・Props・CSS クラス・設定キー・データの項目名は、本文に書かない。

- コードを探す手がかりは「基本情報」の表（ファイル名・コンポーネント名）にまとめる
- 逆向き（コードから画面仕様）は、画面のいちばん上のコンポーネントの先頭コメントで指す（下の「コードからのリンク」）
- 設定は画面上の表示名で書く。キー名や既定値は [設定ファイルの形式](../architecture/file-formats/settings-format.md) へ、データの項目は [ファイル形式](../architecture/file-formats/README.md) へリンクする
- 呼び出し元によって挙動が変わる部品は、その変わり方を言葉で書く

```
Bad:  `window.electronAPI.openItem(item)`を実行
Good: アイテムを実行（開く）

Bad:  `setSelectedIndex(0)`で選択をリセット
Good: 選択を先頭にリセット

Bad:  `handleItemClick`を実行
Good: クリックしたアイテムを開く

Bad:  `if (item.type === 'url')` の場合
Good: URLアイテムの場合

Bad:  `allowEmpty` が true なら空を許可
Good: 呼び出し元の設定によっては、空のままでも有効として扱う

Bad:  録画中は `.recording` クラスを付ける
Good: 録画中は入力欄の見た目が変わる
```

## コードからのリンク

画面のいちばん上のコンポーネント（「基本情報」のファイル名）の先頭に、画面の名前と画面仕様の場所をコメントで書く。部品やフックには書かない。

```ts
/**
 * 画面: 管理ウィンドウ
 * 画面仕様: docs/screens/admin-window.md
 */
```

- コードを直す人が、どの画面仕様を直せばよいかを知る手がかりになる
- `/docs-check` は、変わったファイルから import をさかのぼって最寄りのこのコメントを探し、照合する画面仕様を決める（E）。コメントのない画面仕様や、指す先のないコメントは I で見つかる
- 1 つの仕様書に部品が複数あるとき（共通ダイアログなど）は、`docs/screens/dialogs.md#3-confirmdialog` のようにアンカーまで書く

## コードの写しを書かない

次のものは書かない。コードが正なので、必要ならリンクする。

- Props や型定義の一覧、使用例のコード
- CSS の宣言やクラス名の一覧（スタイルの決まりは [CSS設計](../architecture/css-design.md)）
- IPC チャンネルや設定キーの一覧（[IPC の設計](../architecture/ipc-channels.md)、[ファイル形式](../architecture/file-formats/README.md)）
- `data-testid` の一覧（テストの識別子。E2E テストが正）
- 処理フローの中のコードブロック

````
Bad:
1. `window.electronAPI.readDataFile()`でデータを読み込み
2. `parseItems(data)`でパース
3. 以下のコードでフィルタリング
   ```typescript
   const filtered = items.filter((item) => item.name.toLowerCase().includes(query));
   ```

Good:
1. データファイルを読み込む
2. アイテムの一覧に変換する
3. 入力文字列でアイテム名を部分一致で絞り込む（大文字小文字を区別しない）
````

---

## 書くべきこと

### 処理フロー

機能・挙動を主語にして、順に書く。

```
1. データファイルを読み込む
2. アイコンのキャッシュを当てる
3. アイテムの一覧を表示する
```

### 表示条件・状態遷移

```
- 録画中: 入力欄の見た目が変わり、「録画中...」と表示する
- 無効時: グレーアウトし、クリックしても反応しない
```

### エラーハンドリング

どこに（トースト・ダイアログ・入力欄の下など）、どの文言で出すかを書く。

```
- 保存に失敗したら、エラーのトーストで「アイテムの保存に失敗しました」と表示する
- 入力が足りないときは、入力欄の下に赤字で理由を表示する
```

## 構成

### 章立て

| 章 | 必須 | 内容 |
| ----------------- | :--: | ---------------------------------------------------------- |
| 関連ドキュメント | ○ | 画面一覧と関連する画面へのリンク |
| 1. 概要 | ○ | 目的・主要機能。撮影できる画面は末尾に画面イメージ |
| 2. 基本情報 | ○ | ファイル名・コンポーネント名・表示条件・画面タイプ・親画面 |
| 3. 画面項目一覧 | ○ | エリアごとの項目と表示条件 |
| 4. アクション一覧 | - | 大きな画面（アクションが多いもの）だけ |
| 5. 機能詳細 | ○ | アクションごとの処理フロー・表示条件・エラー |
| 6. キーボード操作 | - | キーボード操作がある場合だけ |

### 見出し番号

- 章は「## N.」、章の中の小見出しは「### N.M.」とし、**小見出しの番号は章の番号に合わせる**
- 必須でない章を省いたときは、後ろの章の番号を詰めて振り直し、文書内のリンク（アンカー）も合わせて直す
- アクション一覧の No は、機能詳細の小見出しの番号と同じにする

番号のずれは点検スクリプト（`/docs-check` の H）で見つかる。

### 新しい画面を足したとき

1. 下のテンプレートから `docs/screens/[kebab-case-名前].md` を作る
2. 画面のいちばん上のコンポーネントに「画面仕様:」コメントを書く（[コードからのリンク](#コードからのリンク)）
3. [画面一覧](./README.md) と [画面遷移](./screen-transitions.md) に足す
4. 撮影できる画面なら、画面イメージを撮る（次節）

## 画面イメージ

画面イメージは手で撮らず、撮影スクリプトで撮る。UI を変えたら撮り直して、画像の差分も PR に含める。

```bash
npm run docs:screenshots   # ビルドしてから撮影し、docs/screens/images/ に上書き保存する
```

- **スクリプト**: `tests/screenshots/screens.spec.ts`（設定は `playwright.screenshots.config.ts`。通常の E2E には含めない）
- **撮影用データ**: `tests/e2e/templates/screenshots/`（データファイル 2 タブ・ワークスペース）。写したいアイテムはここに足す
- **置き場とファイル名**: `docs/screens/images/<仕様書名>[-<状態>].png`（例: `admin-window-items.png`）
- **埋め込み方**: 概要（1 章）の末尾に `### 画面イメージ` を置き、`![画面名（状態）](./images/xxx.png)` で入れる。1 つの仕様書に複数の状態があるときは、画像の前に太字で状態名を書く
- **ネットワーク**: アイコンを写すため、撮影中に Web サイトのファビコンを取得する
- **撮らない画面**: 本人の PC の情報が写る画面（ウィンドウ検索・ウィンドウ選択・ブラウザから直接読むブックマーク取込）は撮らない。右クリックメニューは OS のネイティブメニューで、ページのスクリーンショットに写らないため撮らない

新しい画面を撮るときは、`screens.spec.ts` に `shot(page または locator, '<ファイル名>')` を足す。子ウィンドウ（登録・編集、アイコン取得結果など）は about:blank で開いてから中身を書き込むため、`waitForWindowWith()` で中身の要素が描かれるのを待ってから撮る。

## テンプレート

新しい画面仕様書は、次をコピーして作る。

```markdown
# [画面/コンポーネント名] 仕様書

## 関連ドキュメント

- [画面一覧](./README.md) - 全画面構成の概要
- [関連画面](./xxx.md) - 関連する画面の詳細仕様

<!-- 必要に応じて追加 -->

## 1. 概要

<!-- 画面/コンポーネントの目的と役割を1-2文で説明 -->

**キーボードショートカット**: <!-- 該当するショートカットがあれば記載 -->

### 主要機能

- **機能1**: 説明
- **機能2**: 説明

### 画面イメージ

![画面名](./images/xxx.png)

## 2. 基本情報

| 項目                       | 内容                                                     |
| -------------------------- | -------------------------------------------------------- |
| **ファイル名**             | `src/renderer/components/Xxx.tsx`                        |
| **コンポーネント名**       | `Xxx`                                                    |
| **スタイル**               | `src/renderer/styles/components/Xxx.css`                 |
| **表示条件**               | どのような操作で表示されるか                             |
| **画面タイプ**             | ウィンドウ / 子ウィンドウ / モーダル / コンポーネント    |
| **親画面**                 | 親となる画面名                                           |
| **呼び出し元で変わる挙動** | 部品の場合だけ。呼び出し元の設定で変わる挙動を言葉で書く |

## 3. 画面項目一覧

| エリア       | 項目名 | 内容・説明 | 表示条件 | 機能詳細                |
| ------------ | ------ | ---------- | -------- | ----------------------- |
| **ヘッダー** | 項目名 | 説明       | 常時表示 | [5.1](#51-アクション名) |
| **メイン**   | 項目名 | 説明       | 条件     | [5.2](#52-アクション名) |

## 4. アクション一覧

<!-- 大きな画面（メインウィンドウ、管理ウィンドウ等）の場合のみ。省くときは後ろの章を詰める -->

| No  | アクション名 | トリガー       | 主な処理内容 | 詳細                     |
| --- | ------------ | -------------- | ------------ | ------------------------ |
| 5.1 | アクション名 | ボタンクリック | 処理の概要   | [詳細](#51-アクション名) |
| 5.2 | アクション名 | キー入力       | 処理の概要   | [詳細](#52-アクション名) |

## 5. 機能詳細

### 5.1. アクション名

#### アクション

- ユーザーが行う操作

#### 処理フロー

1. 処理ステップ1（機能・挙動を主語にする）
2. 処理ステップ2

#### 表示条件

- この機能が有効になる条件

#### エラーハンドリング

- エラー時にどこへ何を表示するか

### 5.2. アクション名

#### アクション

- ユーザーが行う操作

#### 処理フロー

1. 処理ステップ1
2. 処理ステップ2

## 6. キーボード操作

<!-- 該当する場合のみ -->

| キー              | 動作             |
| ----------------- | ---------------- |
| Enter             | アクションの説明 |
| Escape            | アクションの説明 |
| ArrowUp/ArrowDown | アクションの説明 |
```
