# アイテムの種別

登録するアイテムの 6 つの種別（単一アイテム・フォルダ取込・グループ・ウィンドウ操作・クリップボード・ウィンドウ配置）と、それぞれで何ができるかの説明です。種別は登録画面の「種別」で選びます。保存される形は [データファイル形式](../architecture/file-formats/data-format.md)、用語は [用語集の「登録種別」](../architecture/glossary.md) を参照してください。

## 単一アイテム

URL、アプリケーション、ファイル、フォルダ、カスタム URI を 1 件ずつ登録します。どれとして開くかはパスの形から決まります。

| 登録できるもの | 例 |
| --- | --- |
| Web サイト | `https://github.com`、`https://www.notion.so` |
| アプリケーション | `C:\Program Files\Google\Chrome\Application\chrome.exe`、`notepad.exe` |
| ファイル | `C:\Users\YourName\Documents\report.xlsx` |
| フォルダ | `C:\Projects`、`C:\Users\YourName\Downloads` |
| カスタム URI | `obsidian://vault/MyVault`、`vscode://file/path/to/file` |

名前は自由に付けられます。検索は名前の部分一致なので、探すときに打つ言葉を名前に入れておきます（例: `https://mail.google.com` を「メール」、`report.xlsx` を「基幹刷新 報告書」）。

アイテムごとに、開いたウィンドウの位置・サイズ・表示するモニター・仮想デスクトップを決めておけます（ウィンドウ制御。仕組みは [ウィンドウ制御](../architecture/window-control.md)）。

## フォルダ取込

指定したフォルダを読み込み、中のファイルやフォルダをそれぞれアイテムとして候補に並べます。フォルダの中身は読み込むたびに反映されるので、ファイルが増えても登録し直す必要はありません。

| 決められること | 例 |
| --- | --- |
| サブフォルダをどこまでたどるか | 現在のフォルダのみ、1〜3 階層下まで、無制限 |
| 取り込む種類 | ファイルのみ、フォルダーのみ、両方 |
| 入れるもの（フィルター） | `*.xlsx`、`*.md` |
| 除くもの（除外パターン） | `旧*`、`temp*` |
| 表示名の前後に付ける文字 | 「基幹刷新 」を前に付けて、プロジェクト名でも当たるようにする |

## グループ

登録済みのアイテムをまとめて一度に開きます。グループはアイテムの名前を参照するだけなので、パスなどは個々のアイテムで管理します。詳細は [グループ起動](./group-launch.md) を参照してください。

活用例:

- 「業務開始」: メール、カレンダー、チャット、エディタをまとめて開く
- 「会議準備」: 会議ツール、議事録の雛形、プロジェクトの資料フォルダをまとめて開く

## ウィンドウ操作

アプリを起動せず、すでに開いているウィンドウをタイトルやプロセス名で探して、前面に出したり位置・サイズを変えたりします。

活用例:

- 散らばったブラウザのウィンドウを決まった位置に戻す
- エディタを特定のモニターに移す

## クリップボード

クリップボードの内容（テキスト、HTML、RTF、画像。画像は 10MB まで）を保存しておき、選ぶとその内容をクリップボードに戻します。

活用例:

- 定型文や署名をすぐ貼り付けられるようにする
- よく使う画像をクリップボードに呼び出す

## ウィンドウ配置

複数のウィンドウの位置・サイズ・仮想デスクトップをまとめて記録し、一度に並べ直します。記録は、いま開いているウィンドウを取り込んで作ります。ウィンドウごとに、アプリを起動して配置するか、開いているウィンドウの位置だけを変えるかを選べます。

活用例:

- エディタ・ブラウザ・ターミナルをいつもの位置に並べ直す
