# トースト通知

ユーザーの操作に対するフィードバックを表示するトースト通知システムです。

## 概要

| 種類 | 表示場所 | 用途 | 特徴 |
| --- | --- | --- | --- |
| **独立トースト** | 画面下部中央（専用ウィンドウ） | アイテム起動など、ウィンドウ閉鎖後も確認が必要な通知 | クリック貫通 |
| **UI内トースト** | メインウィンドウ内 右下（react-hot-toast） | コピー完了、エラー表示など即時フィードバック | ウィンドウを閉じると消える |

---

## 開発者向けガイドライン

### 知らせ方の使い分け（トースト・ダイアログ・画面内の表示）

ユーザーへの知らせは次の 3 つに分ける。OS 標準の `alert()`・`confirm()` は使わない（eslint の `no-alert` が止める）。

| 役割 | 使うもの | 使う場面 |
| --- | --- | --- |
| トースト | 独立トースト・UI内トースト | 操作の結果を知らせる。失敗しても状態は壊れておらず、やり直せば済むもの（起動・コピー・追加・前面に出す失敗など） |
| ダイアログ | [AlertDialog・ConfirmDialog](../screens/dialogs.md) | 読んで対応が要るもの（保存できなかった・外部の変更とぶつかった・ホットキーを登録できない）と、取り消せない操作の確認 |
| 画面内の表示 | 帯・入力欄の下の赤字（`.validation-error`・`.error-message`） | 続いている状態（アイコン未取得の件数・入力の誤り） |

見た目は 3 つとも、種類の色を `variables.css` の `--notify-*`、種類の印を `ToastTypeIcon`（独立トーストは `overlay.html` の同じ記号）で揃える。

### どちらのトーストを使うべきか

- **メインウィンドウが閉じた後も通知を見せたい** → 独立トースト
- **それ以外** → UI内トースト

### メッセージ文言のルール

1. **簡潔に**: 1行で完結する短いメッセージ
2. **結果を明示**: 「〜しました」「〜に失敗しました」
3. **対象を明示**: 何に対する操作かわかるように（例：「パスを」「ショートカットの」）
4. **エラー時は原因を含める**: 可能な場合はエラー詳細を追加（例：`${error}`）

### トースト種類の使い分け

| 種類 | 用途 | 表示時間 |
| --- | --- | --- |
| success（成功） | 操作完了 | 2.5秒 |
| info（情報） | 一般的な情報 | 3秒 |
| warning（警告） | 操作不可、注意喚起、一部だけ失敗 | 4秒 |
| error（エラー） | 操作失敗、例外発生 | 6秒 |

- 表示時間は独立トースト・UI内トーストで共通で、`src/common/constants.ts` の `toastDurationMs` が種類から決める。呼び出し側は数値を指定しない
- 2 行以上になる文・件数や名前を並べる文だけ「長め」（`long: true`）にする。種類の時間に 3 秒足す
- 種類は省かない（独立トーストの `type` は必須）。親フォルダが無い・一部だけ失敗のように、操作が思いどおりにならなかったものは警告にする

## 技術仕様

### UI内トースト（react-hot-toast）

**実装ファイル:**

- `src/renderer/hooks/useToast.ts` - トーストフック
- `src/renderer/components/ToastProvider.tsx` - プロバイダー

- `src/renderer/components/ToastTypeIcon.tsx` - 種類のアイコン（色の丸に記号）

**見た目:** 独立トーストと同じ白地のカード（文字は `var(--text-primary)`）で、種類は左の帯（4px）とアイコンの色で示す。色は `variables.css` の `--notify-*`。

| 種類 | 色 | 記号 |
| --- | --- | --- |
| success | `var(--notify-success)`（緑） | ✓ |
| error | `var(--notify-error)`（赤） | ✕ |
| warning | `var(--notify-warning)`（黄土） | ! |
| info | `var(--notify-info)`（青） | i |

**位置:** ウィンドウの右下（下端・右端から `var(--spacing-lg)`）。管理ウィンドウだけは、アイテム管理の下の件数の帯（ステータスバー。高さ `var(--admin-status-bar-height)`）に重ならないよう、その高さの分だけ上に出す（`ToastProvider` の `bottomOffset`）

### 独立トースト

**実装ファイル:**

- `src/main/services/overlayWindowService.ts` - オーバーレイウィンドウサービス（トーストとセットの進み具合の表示で1ウィンドウを共用）
- `src/main/ipc/notificationHandlers.ts` - IPCハンドラー
- `overlay.html` - オーバーレイ表示用HTML（トースト＋セットの進み具合）

**見た目:** UI内トーストと同じ白地のカードに、種類の色の左の帯と印を付ける（色は `variables.css` の `--notify-*` を `overlay.html` からも読む）。シンプル形式は文言の左に色の丸の記号、アイテム名つきの形式はアイテムのアイコンの右下に小さな印を付ける。

**表示時間:** 種類で決まる（上の「トースト種類の使い分け」）。ウィンドウは表示時間の 0.5 秒後に隠す

**ウィンドウ共用について:** トーストとセットの進み具合のミニウィンドウ（ウィンドウ位置を記録した行があるセットを起動したときに出る）は1枚のオーバーレイウィンドウをモードを切り替えて共用する。進み具合の表示中はトーストを表示しない（進捗表示を優先）。ただし、終わった表示（失敗・中止で「閉じる」を待っているもの）は、次のトーストに置き換わる。非表示のまま5分経過するとウィンドウは破棄され、次回表示時に再作成される。

**プロセス共有について:** オーバーレイウィンドウはメインウィンドウのレンダラーから `window.open` で開かれ、メインとレンダラープロセスを共有する（`src/main/services/childWindowService.ts`）。専用プロセスを持たないため、初回表示時のプロセス起動コストがなく、メモリ消費もDOM分のみ。詳細は [システム概要](../architecture/overview.md#ウィンドウとレンダラープロセスの対応)

**ウィンドウ仕様:**

- サイズ: 400×100px
- 位置: 画面下部中央（マウスカーソルがある画面の下部中央、マージン16px）
- フレームレス・透明
- クリック貫通（マウスイベント無視）

### メインプロセスから出すトースト

画面の操作と関係なく、メインプロセスが状況を知らせるために出す独立トースト。どの画面が開いていても、マウスカーソルがある画面の下部中央に出る。

| きっかけ | 種類 | 表示時間 | メッセージ |
| --- | --- | --- | --- |
| 起動時・F5 の読み込みで、データファイルかワークスペースファイルが壊れていた | エラー | 6 秒 | 設定ファイルの読み込みに失敗しました（破損の可能性）: {ファイル名} |
| 読み込みでスキップしたアイテム、ID を採番したアイテム、または深すぎる・循環するため最上位へ移したワークスペースのグループがあった | 警告 | 7 秒（長め） | データ: {N} 件読み込み・{M} 件スキップ・{K} 件に ID を採番・深すぎる・循環するグループ {L} 件を最上位へ移動（0 件の部分は出さない）。QDL の外での変更を検知したときは先頭が「外部編集されたデータ」。ほかの補正（`normalized`）ではトーストを出さない |
| QDL の外で設定ファイルが変わったあとの F5 で、ホットキーを登録し直せなかった | エラー | 6 秒 | {ホットキーの種類}「{新しいキー}」を登録できません（{理由}）。「{今のキー}」を維持します（同じキーの失敗は 1 回だけ知らせる） |
| ワークスペースの操作が、外部での変更・破損・再読み込み中・書き込み失敗で止まった | 警告 | 7 秒（長め） | 例: {ファイル名} が QDL の外で変更されています。メイン画面で F5 を押して再読み込みしてから操作してください（破損・再読み込み中・書き込み失敗もそれぞれの理由を出す） |
| 起動時のブックマーク自動取込で、追加・更新・削除のどれかがあった、またはエラーがあった | 情報（エラーがあれば警告） | 3 秒（手動分と重複があれば長めの 6 秒） | {N} 件追加、{U} 件更新、{M} 件削除（0 件の区分は省く。手動分と重複があれば「、手動分と重複 {K} 件」、エラーがあれば「（一部エラー）」を付ける）。変化もエラーも無ければ出さない |
| CLI（qdl）でアイテム・ワークスペース・タブ・設定を書き込んだ | 成功 | 2.5 秒 | 例: CLI: メインウィンドウに「{名前}」を追加しました／CLI: ワークスペース「{名前}」を変更しました（失敗・`--dry-run`・読むだけのコマンドでは出さない） |
| 管理画面の設定で「QuickDashLauncher CLI を使えるようにする」を切り替えた | 成功 | 2.5 秒 | オン: QuickDashLauncher CLI を使えるようにしました。新しく開いたターミナルから qdl で使えます／オフ: QuickDashLauncher CLI を使えないようにしました（qdl コマンドを PATH から外しました） |
