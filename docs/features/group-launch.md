# グループ起動機能

複数のアイテムをまとめて一括起動する「グループ」機能の詳細説明です。

## 概要

グループ機能を使うと、複数のアプリケーション、Webサイト、フォルダ、ファイルを1つのグループとして定義し、一度の操作でまとめて起動できます。

### 主な特徴

- **参照ベース設計**: グループは既存アイテムの名前を参照するため、アイテム情報の重複がありません
- **2つの起動モード**: 順次実行（デフォルト）または並列実行を選択可能
  - **順次実行**: 定義順に起動し、各アイテム間で100ms待機（起動順序が保証される）
  - **並列実行**: 全アイテムを同時に起動（高速だが順序は保証されない）
- **DRY原則**: アイテムのパスや設定はすべて個別定義で管理され、グループは名前のみを参照
- **柔軟な組み合わせ**: 通常アイテム（URL、アプリ、フォルダ、ファイル、カスタムURI）とウィンドウ操作アイテムを組み合わせ可能。グループ・クリップボード・ウィンドウ配置は起動されません

## 起動モードの設定

グループの起動モード（順次実行または並列実行）は、アプリケーション設定で変更できます。

### 設定方法

1. **管理画面を開く**: `Ctrl+E`
2. **設定タブを選択**: 画面上部のタブから「⚙️ 基本設定」を選択
3. **基本設定カテゴリ**: 左側メニューで「⚙️ 基本設定」を選択
4. **グループ起動セクション**: 「グループアイテムを並列起動」のチェックボックスを切り替え
5. **自動保存**: チェックボックスの変更は即座に自動保存されます

### 起動モードの選び方

**順次実行（デフォルト）を選ぶべき場合:**

- アイテムの起動順序が重要な場合
- 一部のアイテムが他のアイテムに依存している場合
- システムリソースを節約したい場合

**並列実行を選ぶべき場合:**

- アイテムの起動順序が重要でない場合
- すべてのアイテムが独立している場合
- グループ起動を高速化したい場合

## 使用例

グループは、グループ名と「含めるアイテム名」で定義します。含めるアイテムは、同じデータファイル内の既存アイテムの表示名で指定します。JSON での実際の記述は [データファイル形式仕様](../architecture/file-formats/data-format.md#33-グループアイテムjsongroupitem) を参照してください。

### 基本的な使用例

- 個別アイテム: Visual Studio Code、Slack、Chrome（`--new-window https://localhost:3000` 付き）、開発フォルダ（`C:\dev`）
- グループ名: 開発環境
- 含めるアイテム名: Visual Studio Code、Slack、Chrome、開発フォルダ

この例では、「開発環境」グループを実行すると（順次起動モードの場合）：

1. Visual Studio Codeが起動
2. 100ms待機
3. Slackが起動
4. 100ms待機
5. Chromeが起動（localhost:3000を開く）
6. 100ms待機
7. 開発フォルダが開く

### 複数のグループを定義する例

- 個別アイテム: Zoom、Teams、議事録フォルダ、Google、GitHub、Gmail
- グループ「会議準備」: Zoom、Teams、議事録フォルダ
- グループ「Web閲覧」: Google、GitHub、Gmail

### 実際のユースケース

**プロジェクトごとの起動設定:**

- 個別アイテム: VSCode ProjectA、Chrome ProjectA、ProjectA Folder
- グループ「ProjectA起動」: VSCode ProjectA、Chrome ProjectA、ProjectA Folder

**業務開始時の一括起動:**

- 個別アイテム: Outlook、Teams、社内ポータル、タイムカード
- グループ「業務開始」: Outlook、Teams、社内ポータル、タイムカード

## UI表示

### メインウィンドウでの表示

グループアイテムは、アイテムリストに以下のように表示されます：

- **アイコン**: 📦（固定）
- **背景色**: 水色系（他のアイテムと視覚的に区別）
- **左境界線**: 青色の強調線
- **表示名**: `グループ名 (N個)`
  - 例: `開発環境 (4個)`
- **ツールチップ**: マウスホバーで詳細情報を表示
  - グループに含まれるアイテム名の一覧
  - データファイル名（data.json または data2.json）
  - アイテムID

### ツールチップの表示例

グループアイテムにマウスをホバーすると、以下のような情報が表示されます：

```
グループ: Visual Studio Code, Slack, Chrome, 開発フォルダ

データファイル: data.json
ID: abc123
```

### 実行方法

1. **検索してEnter**: 検索ボックスにグループ名を入力してEnterキー
2. **矢印キーで選択してEnter**: ↑↓キーで選択してEnterキー
3. **クリック**: マウスでグループアイテムをクリック

## アイテム管理での編集

アイテム管理画面（Ctrl+E）でグループを作成・編集できます。

### 新規グループの作成

1. **アイテムを追加**: ➕アイテムを追加ボタンをクリック（単一アイテムとして先頭に追加される）
2. **詳細編集**: 追加された行の✏️ボタンで詳細編集モーダルを開き、種別で「グループ」を選ぶ
3. **入力**: グループ名と、含めるアイテム名を入力して更新
   - グループのアイテム名リストはセルでは編集できない（パス列は読み取り専用で、ダブルクリックすると詳細編集が開く）。詳細編集から編集する
4. **保存**: 保存ボタン（または Ctrl+S）で確定

### 詳細編集モーダルでの編集

✏️ボタンをクリックするとRegisterModalが開き、より詳細な編集ができます：

1. **種別選択**: 「グループ」を選択
2. **グループ名**: グループの表示名を入力
3. **グループアイテムリスト**: 選んだアイテム名がチップで並びます
   - 「+ アイテムを追加」でグループアイテム選択モーダルを開き、既存アイテムから選ぶ
   - チップの×で外す
4. **保存先**: 「保存先タブ」で設定済みのタブから選ぶ（複数ファイルのタブでは「保存先ファイル」も選ぶ）
5. **更新**: 更新ボタンで管理画面に反映（この時点では保存されない）。保存ボタン（または Ctrl+S）で確定

### 既存グループの編集

1. グループ行の✏️ボタンをクリック
2. RegisterModalで内容を編集
3. 更新ボタンで管理画面に反映し、保存ボタン（または Ctrl+S）で確定

### グループの削除

1. グループ行のチェックボックスを選択
2. 🗑️選択したアイテムを削除ボタンをクリック
3. 確認ダイアログでOK

## エラーハンドリング

### 存在しないアイテム名を参照している場合

個別アイテム「Visual Studio Code」「Slack」だけが存在する状態で、グループ「開発環境」が存在しない「Chrome」も含めている場合：

**動作:**

- Visual Studio Codeが起動
- Slackが起動
- "Chrome"は存在しないため、警告ログを出力してスキップ
- グループ実行は継続（エラーで停止しない）

警告ログは、グループに書かれた名前と同じ表示名の通常アイテム・ウィンドウ操作アイテムが読み込み済みのアイテムの中に無いときに、グループ名とアイテム名を添えて記録されます（名前が一致してもグループ・クリップボード・ウィンドウ配置は対象外なので、同じく警告になります）。ウィンドウ操作アイテムで対象のウィンドウが見つからなかったときも、別の警告が記録されます。

### 部分的なエラー

グループ内の一部のアイテムが存在しない場合でも、残りのアイテムは正常に起動されます。

## 設計上の利点

### DRY原則（Don't Repeat Yourself）

グループは参照ベース設計のため、アイテム情報の重複がありません。

- **悪い例（重複あり）**: グループ側にアプリのパスや引数を直接書く（個別アイテムと情報が重複する）
- **良い例（参照ベース）**: 個別アイテム（Visual Studio Code、Slack、Chrome）を定義し、グループ「開発環境」はその名前だけを参照する

### 保守性

アイテムのパス変更時は個別アイテムのみ修正すればOKです。例えば Visual Studio Code のパスが変わった場合は、個別アイテム「Visual Studio Code」だけを修正し、グループ「開発環境」は変更不要です。

### 可読性

グループの定義が名前の一覧だけで済むため、何を起動するかが一目でわかります（例: グループ「朝の業務開始」= Outlook、Teams、社内ポータル、タイムカード）。

### 一貫性

グループで起動するアイテムは、個別に起動した場合と完全に同じ動作を保証します。

## コンテキストメニュー

グループアイテムを右クリックすると、編集用のコンテキストメニューが表示されます。

### メニュー項目

- **✏️ 編集**: グループ編集モーダルを開く
- **📝 メモを表示**: アイテムに設定されたメモを表示する（メモが設定されている場合のみ表示）
- **⭐ ワークスペースに追加**: グループアイテムをワークスペースウィンドウに追加する

### 動作

- グループアイテムの場合、パス関連のメニュー項目（親フォルダーを開く、パスをコピー等）は非表示になります
- 編集・ワークスペース追加・メモ表示のメニューが表示され、グループの内容を変更・管理できます

## 制限事項

### 現在の制限

1. **起動間隔固定**: 順次実行時の起動間隔は100ms固定（カスタマイズ不可）
2. **グループのネスト不可**: グループ内でグループは参照できません
3. **カスタムアイコン非対応**: グループアイテムのアイコンは📦固定です
4. **並列起動の順序**: 並列起動モードでは起動順序が保証されません

### 並列起動の注意事項

- **順序依存**: アイテム間に依存関係がある場合は順次実行を使用してください
- **リソース消費**: 多数のアイテムを並列起動すると、一時的にシステムリソースを多く消費します
- **ウィンドウ配置**: 複数のウィンドウを同時に開く場合、ウィンドウの重なり方が予測しづらくなります

## ベストプラクティス

### 1. 意味のあるグループ名をつける

- **悪い例**: `group1`（何を起動するか分からない）
- **良い例**: `開発環境`

### 2. 起動順序を考慮する

重いアプリケーションを先に起動し、軽いアプリや特定のURLを後に起動することで、スムーズな起動体験を実現できます。

- 例（重い→軽い の順）: グループ「開発環境」= Visual Studio Code、Docker Desktop、Chrome、Slack

### 3. 用途別にグループを分ける

1つの大きなグループより、用途別に小さなグループを作成した方が柔軟です。

- **悪い例**: グループ「全部」に App1〜App8 をすべて入れる
- **良い例**: 「開発環境」（VSCode、Docker、Chrome）、「コミュニケーション」（Teams、Slack、Zoom）、「業務ツール」（Outlook、社内ポータル、タイムカード）に分ける

### 4. グループ名は検索しやすくする

グループを素早く起動できるよう、短く検索しやすい名前にします。

- **悪い例**: `毎朝の業務開始時に使用する一連のアプリケーション群`
- **良い例**: `朝の起動`、`業務開始`（さらに短く）

## トラブルシューティング

### グループが実行されない

**原因1: グループ内のアイテム名が間違っている**

- data.jsonを確認し、参照しているアイテム名が正確か確認
- 大文字小文字、スペースの有無に注意

**原因2: グループ構文が間違っている**

- data.json の JSON 構文や `itemNames` が誤っていないか確認

### 一部のアイテムだけ起動されない

**原因: 存在しないアイテム名を参照している**

- アイテム管理画面（Ctrl+E）でグループ行を確認
- ✏️ボタンで詳細編集し、アイテム名リストを修正

### グループアイテムが表示されない

**原因: data.jsonの構文エラー**

- アイテム管理画面でグループ行が正しく認識されているか確認
- 行の種類が「グループ」と表示されているか確認
